Step 02

Decision: three tests, four games.

Test 01 · Re-skinWink Wink & Nod the BeatTwo similar games with different inputs and themes: a wink on a city walk, head moves at a party. Tests the re-skin flow.
Test 02 · VoiceAh! JumpSports with a voice trigger, the most popular input and the quickest to land.
Test 03 · 3DPanic SalonA 3D look, reflex play and an evergreen theme. Runs the whole loop in 3D.
Step 03

Execution: one loop, two runs.

Same four steps both times. The 2D games share one engine; the 3D one runs the same loop with models.

01Idea → greybox → playability
  • Describe the loop to Claude Code in plain words, get a rough version with real tracking and no art.
  • Play it until the input feels right, then reuse the engine for the next game with a new input and theme.
  • Ah! Jump started the same way: voice instead of eyes, a rope instead of lanes.

“A rhythm game for the left and right eye. Close an eye to hit the beat on that side. Both eyes for the drop. Build a rough version I can play.”

Wink Wink, the first brief.
Greybox, kept online ↗

“Same idea, new input: tilt left, tilt right, nod for the drop. Put it in a DJ booth. Check that it still plays.”

Nod the Beat, once Wink Wink felt right.

02Art and audio
  • One reference image in, and Codex draws the rest: pedestrians in two states, the booth, the hands, the crowd, the stickers.
  • Ah! Jump needed three bodies, a court, and hair split into a still cap and swinging parts on one shared frame.
  • Sound starts in code — the groove, the hit riff and the crowd are WebAudio, quick to tune while the loop still moves.
  • When a playtest says a cue is not landing, swap in a free-for-commercial-use effect or track.
03Integrate, spec, iterate
  • Claude Code reads the TikTok Effect spec in Figma, then builds each game's frames there with me.
  • It fits the game to the spec, so the build shows what the effect looks like inside TikTok.
  • Friends play it on their own phones, and their notes keep tuning the pace, the sound and the inputs.
